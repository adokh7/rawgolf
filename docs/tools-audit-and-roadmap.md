# GolfRaw Tools: Audit, Demand Analysis and Freemium/Pro Roadmap

*13 September 2026. Audit performed against `main` at fd4597e, live design.*

## 1. Codebase audit

Twelve interactive tools plus the hub (`tools.html`). All are static, client-side,
zero-login pages. Nine share `rawgolf-tools.js` (share/download/clipboard helpers);
three are generated by build scripts and must be edited there, never in the HTML
(`build_standing_order.py`, `build_tendency_engine.py`, `build_field_reader.py`).
All twelve load the Locker (local-first IndexedDB storage in `lib/locker/`); three
carry a write bridge so what you enter persists and flows to the other tools.

### Method

Every tool was loaded in a browser, driven with realistic inputs through its primary
action, and its console captured. Every inline script was also parsed with `node
--check`. Each page was then rendered at 375px and measured for horizontal overflow,
scroll containment and touch-target size. This is a smoke test of the happy path,
not a numerical verification of each formula.

### Results

| Tool | Primary action drove a result | Console errors | Mobile | Persists |
|---|---|---|---|---|
| Bag Audit | Yes: dead-wood score, gap/overlap detection | 0 | clean | Locker (bridge) |
| Standing Order | Yes: 6 shots logged, median + dispersion bars rendered | 0 | club strip scrolls (intended) | Locker |
| Tendency Engine | Yes: 18-hole stepper, tendencies + verdict | 0 | clean | Locker |
| Field Reader | Yes: 4 sliders re-rank a 12-row board | 0 | clean | picks on device |
| Handicap Lie Detector | Yes: WHS index, claimed vs calculated | 0 | delete buttons were 36px, fixed | Locker (bridge) |
| Plays Like | Yes: live recalculation, club suggestion | 0 | preset chips were 34px, fixed | Locker (bridge) |
| Round Autopsy | Yes: strokes-lost split + cause of death | 0 | scorecard scrolls (intended) | localStorage |
| Settle Up | Yes: who-owes-who card | 0 | 18px checkboxes, fixed; card scrolls (intended) | localStorage |

| Tilt Meter | Yes: tilt index, bounce-back rate | 0 | clean | localStorage |

**Technical health: twelve of twelve functional, zero runtime errors, zero syntax
errors, zero missing dependencies, no page-level horizontal scroll on any tool.**
The only defects found were sub-40px touch targets on four tools; those are fixed in
this commit through the theme layer (touch floors on chips, delete buttons,
checkboxes and range inputs).

Two things the audit did *not* find and should be said plainly: no tool is
incomplete or stubbed, and no tool depends on a third-party runtime. The suite is in
better shape than a typical "ship it and forget it" calculator collection.

### Structural observations

- **Three storage systems.** The three newest tools use the Locker; six older ones
  use raw `localStorage`; three persist nothing. That is invisible to readers today
  and becomes the first thing a paid tier has to unify (Section 4).
- **Two shell generations.** Older tools carry their own CSS; newer ones link
  `tool-premium.css`. The global theme layer papers over the difference.
- **Field Reader ships archetypes, not players.** Its `tournament-field.json` is
  deliberately synthetic. It is honest about that on the page, but it means the tool
  cannot rank a real field until someone loads sourced strokes-gained numbers.

## 2. Demand analysis

What follows separates what the sources actually support from what is inference.

### Everyday golfers (B2C)

The gapping session is the one pre-round calculation with a named, repeatable
workflow across the industry: warm up, hit five to ten normal shots per club, drop
the mishits, take the median, repeat for every full-swing club, and look for 10 to
15-yard gaps ([FlightScope](https://flightscope.com/blogs/blogs/master-the-carry-distance-gapping-between-your-clubs),
[MG Golf](https://mggolf.com/blogs/the-fairway-report-golf-news-tips/golf-club-gapping-guide)).
Everyone from [MyGolfSpy](https://mygolfspy.com/news-opinion/instruction/golf-club-gapping-tool/)
to [ProYardages](https://proyardages.com/tools/golf-club-distance-calculator/) and
[Golfissimo](https://www.golfissimo.co/golf-club-distance-gapping-tracker/) publishes a
free gapping chart or calculator, which tells you two things: the search intent is
real and durable, and a free gapping tool alone is table stakes, not a moat.

The Standing Order already implements exactly that workflow, with medians and an
80% band rather than averages. That is a genuine differentiator that none of the
free charts above offer, and it costs the reader nothing.

Handicap and "what did I really shoot" calculators, plays-like adjustment, and tee
selection are the other evergreen pre-round searches. GolfRaw has one of each.

### Serious players, coaches and fitters (B2B)

The data gap here is well defined by the market that has grown to fill it.
Third-party platforms now exist purely to ingest launch-monitor CSV exports —
TrackMan, Foresight GC-series, FlightScope Mevo, Garmin R10/R50, Rapsodo, SkyTrak,
Bushnell, Uneekor — and turn them into dispersion maps, cluster analysis and
organised session history for coaches and fitters
([Up Your Club](https://www.upyourclub.com/features/),
[FlushLab](https://flushlabgolf.com/blog/blog-trackman.html)). TrackMan itself
exposes CSV export for exactly this purpose. Hobbyists are building their own
importers on forums
([Golf Simulator Forum](https://golfsimulatorforum.com/forum/off-topic/all-off-topic/417394-built-a-small-tool-to-understand-my-sim-data-curious-for-opinions)).
The pain is not "I cannot get the numbers"; it is "the numbers live in a CSV and my
client needs a one-page answer".

Strokes-gained benchmarking against a chosen handicap tier (scratch, 5, 10, 15, 20,
25) is the established consumer expectation, set by Shot Scope and Arccos on
hundreds of millions of tracked shots
([Shot Scope](https://shotscope.com/blog/practice-green/stats-and-data/understanding-strokes-gained/),
[Golf Digest](https://www.golfdigest.com/story/new-stat-tracking-features-from-arccos--shot-scope-make-you-smar)).
GolfRaw cannot and should not fabricate a shot database to compete with that. What
it can do is the thing those apps do badly: explain the number and turn it into a
decision.

Willingness to pay exists but is fragile. Arccos sells a hardware-plus-subscription
model and reports meaningful handicap improvement for members; the same product
draws recurring complaints about rising annual fees and trial auto-renewal
([Tom's Guide](https://www.tomsguide.com/wellness/fitness/my-favorite-golf-product-is-usd50-off-right-now-its-time-to-try-arccos),
[Trustpilot](https://ca.trustpilot.com/review/arccosgolf.com)). Inference, not
sourced: a low-priced, honest, no-hardware tier positioned against that frustration
has room, but only if the free tools stay genuinely free and the paid tier sells
outputs (reports, exports, history) rather than locking arithmetic.

### Useful versus gimmick

| Genuinely useful (solve a recurring problem) | Entertaining (share-bait, low repeat use) |
|---|---|
| Standing Order, Bag Audit, Plays Like, Handicap Lie Detector, Round Autopsy, Tendency Engine, Settle Up, Tee Box Check | Grudge Match, Tilt Meter, Gimme Audit |
| Field Reader is useful only once it holds real data | |

"Entertaining" is not a pejorative. Those three earn links and shares, which is the
job of the free tier. They should not be built on, and they should never be paid.

## 3. Tiering matrix

### Tier 1: free, forever, no login

Purpose: rank, earn links, capture the top of the funnel, seed the Locker.

All twelve current tools stay free. Specifically keep 100% free: Bag Audit,
Standing Order (logging and gap view), Plays Like, Handicap Lie Detector, Tee Box
Check, Round Autopsy (single round), Tendency Engine (last round), Settle Up, Gimme
Audit, Tilt Meter, Grudge Match, Field Reader.

Rule: a free tool is never crippled to sell Pro. Pro sells what the free tool
*produces over time*, not the calculation.

### Tier 2: GolfRaw Pro

Purpose: turn accumulated Locker data and coach/fitter workflows into revenue.

Gate these, and only these:

1. **History and profiles.** Unlimited saved sessions, rounds and scorecards with
   trend lines across months; multiple bags; a synced backup of the Locker. Free
   keeps the last session/round on-device.
2. **Launch-monitor import.** Paste or upload a TrackMan, Foresight, Garmin,
   FlightScope, Rapsodo or SkyTrak CSV into the Standing Order and get medians,
   80% bands and gap analysis per club, mapped to the user's bag. This is the
   feature the B2B market has proven people pay for.
3. **Coach and fitter report.** A branded, one-page PDF: gapping chart, dispersion
   bars, bag recommendation, tendency summary, with the coach's name and the client's
   name. Exportable and shareable by link.
4. **Advanced modelling.** Monte Carlo dispersion on the Standing Order data (what
   a "plays like" number really means when your 7-iron has a 14-yard band) and
   handicap-tier strokes-gained context on the Tendency Engine.

Suggested price shape: a single Pro tier at a low annual price for players, and a
Coach plan with client folders and unbranded reports. Prices are a business
decision and are deliberately not proposed here.

## 4. Roadmap

### Keep and polish now

- **Standing Order** is the center of gravity: it already computes medians, bands,
  gaps and writes to the shared bag. Everything Pro builds on it.
- **Bag Audit** and **Tendency Engine** are the other two Locker-native tools;
  they are the reason a profile is worth paying for.
- **Round Autopsy** and **Handicap Lie Detector** should migrate from
  `localStorage` to the Locker so their history is part of the same profile.

### Prune

Nothing should be deleted. Every tool page is indexed and functional; removing one
trades real traffic for tidiness. Instead, demote the three entertainment tools on
the hub below the utility tools, and stop investing in them.

### Build next: Launch-Monitor Import into the Standing Order

Highest leverage, lowest build cost, clearest willingness to pay. The Standing
Order already has the maths, the bag mapping, the chart and the Locker write. The
work is a CSV parser for the six common export formats, a column-mapping step, and
the same output. It converts the tool from "tap in numbers at the range" to "drop
in your session", which is what fitters and serious players actually do. The coach
PDF report follows directly from it.

### Paywall and sessions without bloating a static site

The site is static and the Locker is local-first, so the design keeps it that way:

1. **Payment**: Stripe Checkout (hosted page; no card data touches the site). A
   Vercel serverless webhook (`api/pro/webhook.js`) receives the completed session.
2. **Entitlement**: the webhook signs a compact token (`sub`, `plan`, `exp`) with
   an HMAC secret, exactly as the email unsubscribe tokens already are, and stores
   `customer -> plan` in Vercel KV. The token is delivered by a magic link to the
   purchase email.
3. **Client side**: the Locker stores the token in its `meta` store. Pro features
   check `expiry` and `plan` locally for instant gating; nothing about a free user
   changes. This adds one small function to `store.js` and bumps `VER`.
4. **Server-verified outputs**: PDF reports and CSV imports run through a
   serverless function that verifies the token before working. Anything that is
   only client-side gating is treated as convenience, not security, which is fine
   because the value is in the outputs.
5. **Sync**: Pro users can push an encrypted Locker export to KV keyed by the
   token subject, and pull it on another device. Free users keep JSON export/import.

No accounts table, no passwords, no session cookies, no framework. Four serverless
functions, one KV namespace, two new Locker methods.

### Not in this commit

Pro itself. This commit ships the audit, the touch-target fixes and this document.
Building the import, the report and the payment path is the next project and
should be scoped and approved on its own.
